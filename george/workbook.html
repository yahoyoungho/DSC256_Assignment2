Steam genre recommendation: nine-genre experiments¶

George's independent implementation following the November 25 meeting. Question: Do recency, latent preferences or transitions improve recommendations beyond a user's long-term genre mode?

Given positive review history before a cutoff, recommend one genre. A hit means it belongs to a later positively reviewed game's genre set. This is a review-derived preference proxy, not a directly observed favorite genre or causal satisfaction measure.

Exploratory evaluation: Overlapping test events were inspected in the original ten-genre prototype. Changing the genre vocabulary does not make them an untouched test. This run selects settings, checkpoints and ensemble weights on validation only.

1. Model decision and data cleanup¶

At least 75% of the 701,884 raw authors have only one review. Start with history profiles and a shared logistic model, then test latent/sequential models empirically. No architecture is assumed best in advance.

Inputs are the local reviews, applications, application_genres and genres CSVs. The manifest does not verify upstream sampling, source URL or license; these remain team questions. Authors are the user data, not complete user game libraries.

Preserve IDs as strings. Validate dates against a broad year-2000 lower bound, creation/update order, and the row's extraction timestamp. Deduplicate review IDs and user–game pairs, keeping the latest state. Keep games, usable genres, and positive votes. Negative reviews do not imply dislike of every genre and are excluded from preference counts. Removal counts below are sequential.

Normalize translated genre labels into Action, Adventure, Casual, Massively Multiplayer, RPG, Racing, Simulation, Sports and Strategy. Remove Indie, release/business-model labels, content descriptors and software/video labels. Indie + Action stays as Action. Drop a game only if no approved genre remains. Unknown source IDs fail validation; approved rare genres are retained.

All eligible target labels count as correct; no arbitrary primary-genre priority. The earlier 58.13% result allowed Indie and is not directly comparable.

2. Temporal protocol and historical features¶

Global chronological partitions approximate 70/15/15, with timestamp ties together. Event time is max(creation, update), since only the final vote state is available. This predicts later available review states, not play order. Current genre metadata and missing edit histories prevent a fully historical replay.

Every main model uses frozen histories. Fit on training; tune on validation; refit on train + validation using selected epoch counts; score test. Simultaneous reviews form a genre basket, and transitions always originate at a strictly earlier timestamp.

Logistic training creates three disjoint target windows inside fitting data, beginning at its 40%, 60% and 80% timestamps. Features freeze at each window's start. A target never enters its own profile. Inputs are long-term genre rates, 90-day-half-life rates, last genre set, recent global rates, log history length and log review age. Fixed feature scaling does not require fitting transforms on test data.

3. Models, implementation and optimization¶

Family Implementation
Uniform random Stable seeded per-user random ranks.
Global mode Most frequent training interaction–genre membership.
Recent popularity Mode in 30/90/180 days before the cutoff.
User mode Most frequent genre in positive user history.
Repeat last Last basket's genre indicators; training-frequency tie break.
Recency profile Weights 2^(-age_days / half_life), half-life 30/90/180 days.
Fractional profile One total vote per reviewed game.
Markov-1 Source-basket transitions smoothed toward global rates; alpha 0.1/1/10.
Logistic PyTorch linear layer with nine outputs, binary cross-entropy with logits.
MF-BPR User and genre factors plus genre bias; no sequence term.
FMC-BPR Factorized previous-to-next genre transitions, no user factor.
FPMC-BPR Preference and transition factors together.
Ensemble Validation-selected weighted ranks from two leading families.

BPR is an objective, not an architecture or literal SVD. A nine-column genre matrix has rank at most nine; dimensions 2/4/8 are tested. The loss averages every pair of present versus absent target genres. An absent genre is not on this event; it is not assumed to be a lifelong dislike. Previously liked genres remain eligible.

MF/FPMC estimate user factors only with at least two fitting reviews; other users receive profile fallback. Nobody is removed from evaluation. FMC shares transition factors. All learned models use the global prior for users with no positive history. Factor results therefore include explicit hybrid fallback behavior.

Training uses Adam, user-balanced examples, explicit L2, batches up to 8192, a 12-epoch cap and validation patience 3. Staged searches test dimensions, learning rates and L2 rather than a full Cartesian product. Shortlisted settings run with seeds 2026/2027/2028; their ranks are averaged. Each seed's epoch uses validation. Several fits hit the cap; this is a bounded first search, not proof of convergence.

Rank averaging handles incomparable probability/logit scales but discards score magnitude. Markov-2, game-level Jaccard and deep networks remain future extensions.

4. Evaluation and results¶

Primary: binary Hit@1 averaged within users, then across users. Secondary: review-weighted Hit@1, user-averaged NDCG@3, genre coverage, per-genre support and precision/recall, and history cohorts. NDCG@3 evaluates an optional ranking; the product output remains one genre. Uniform random expected Hit@1 is target-set-size/9.

Paired bootstrap intervals resample users, preserving within-user dependence. They do not account for shared games, model-selection uncertainty or time shift.

5. Robustness and alternative protocol¶

Minimum history is a cohort, not an exclusion of the full population. Earlier 50–60% and 60–70% time windows are evaluated with fixed selected settings: these are retrospective diagnostics, not independent nested cross-validation. Unedited review sensitivity uses the same calendar boundaries and fixed baseline settings.

Sequential replay separately reveals a review only after prediction and updates per-user history. Simultaneous reviews are revealed together. Learned parameters, global priors and transition matrices stay frozen; cohorts refer to history at the original cutoff. No replay result selects the winner.

6. Reproduction and inference¶

Run experiments.py, diagnostics.py, verify.py, then build_report.py with the local virtual environment. experiment_config.json, requirements-lock.txt, code/data hashes, checkpoint metadata and seed results record the run. The evaluation model fits train + validation; the deployment model refits all positive data only after evaluation. Every original identifiable user receives a genre.

Numeric NPZ snapshots need no pickle. Unknown IDs get global fallback. Incorporating new history requires rebuilding the batch snapshot; this is not an online service. Model scores are ranking values, not calibrated enjoyment probabilities.

7. Tradeoffs, related work and assignment status¶

  • Gameplay genres are more interpretable than Indie, but exclude games lacking any approved label and still simplify diverse interests into broad categories.
  • Review sampling and positive-only feedback can bias results; there is no full ownership/play history. Lifetime playtime/ownership totals and target review text are not predictive inputs because of availability/leakage concerns.
  • Update time is conservative for final-vote availability, but is not play order. Snapshot genres and missing edit histories limit historical validity.
  • Shared logistic coefficients support sparse histories. User factors require fallback behavior, and the bounded search does not establish universal rankings.
  • An ensemble adds storage/inference cost for little improvement over user mode. Rank averaging sacrifices score magnitude to avoid mixing incompatible scales.
  • A genuinely untouched final test needs new data or an uninspected period.

BPR (Rendle et al., 2009) motivates pairwise ranking. Our nine-genre adaptation enumerates all event-specific positive/negative pairs rather than sampling a large item space. FPMC (Rendle et al., 2010) combines preference and transition factors. Our genre baskets, sparse-user fallback and protocol differ from the original benchmark; published scores are not comparable. PyTorch BCEWithLogitsLoss supplies the logistic model's multi-label training loss.

The assignment PDF requests task definition, EDA, modeling, evaluation, related work, an HTML notebook, a roughly 20-minute recorded presentation and peer grading. This report supports the technical sections. The team still needs verified data provenance, integrated group findings, the recording and real video URL, and peer grading.
