Steam genre recommendation — George's first experiment

Meetup preparation: model choice, independent data cleanup and analysis, global-mode baseline, and a chronological holdout. This is an executed prototype report, not the completed group presentation or final related-work survey.

1. Predictive task and model decision

Given a user's past positive game reviews, recommend one Steam genre. A future positive review supplies a set of acceptable genre labels. Success means the recommendation belongs to that set. We do not observe a user's true favorite genre, and we are not predicting the genre of a supplied target game.

Before modeling, inspection found 1,048,148 reviews and 701,884 authors; at least 75% of authors have only one review. A content-based genre-frequency profile is a suitable initial family because it can work with a single prior interaction and supports a transparent global fallback. We compare its unsmoothed and smoothed variants rather than assuming a more complex model will win.

Model familyDecision before evaluation
Global genre modeRequired baseline, cold-start fallback.
Personal genre mode / smoothed profilePrimary candidates; small vocabulary, interpretable preferences.
Collaborative filtering / factorizationUseful future benchmark; very sparse user histories are a challenge. Not empirically ruled out.
Text or neural modelNot justified as a first step. Target-review text would leak information unavailable at recommendation time.

“Best” below means best validation performance among the six tested configurations, not best among all recommender systems.

3. Model formulation and implementation

Let c(u,g) count the user's positive reviews whose games have genre g, n(u) count their positive reviews, and p(g) be the corresponding global membership rate. Score g by (c(u,g) + alpha * p(g)) / (n(u) + alpha) and select the largest score. An unseen user gets p(g). These are membership-rate estimates, not a probability distribution over mutually exclusive classes.

Alpha=0 is personal mode. The global-only baseline always picks the most frequent training genre. Ties use global frequency, then alphabetical order. Validation maximizes user-averaged Hit@1 over the fixed grid; ties prefer the simpler candidate. Count aggregation costs O(number of interaction–genre memberships), with O(users × genres) profile storage and scoring. This is small compared with learning one embedding per game and user, though it cannot discover preferences absent from the selected genre representation.

import inspect
print(inspect.getsource(GenreRecommender.fit))
print(inspect.getsource(GenreRecommender.predict))
    def fit(self, interactions, game_genres):
        if interactions.empty:
            raise ValueError('Cannot fit without positive training reviews')
        self.genres = sorted(game_genres.genre.unique())
        expanded = interactions[['author_steamid', 'appid']].merge(game_genres, on='appid')
        self.global_counts = expanded.genre.value_counts().reindex(self.genres, fill_value=0)
        self.prior = self.global_counts.to_numpy(dtype=float) / len(interactions)
        self.counts = pd.crosstab(expanded.author_steamid, expanded.genre).reindex(columns=self.genres, fill_value=0)
        self.history = interactions.groupby('author_steamid').size()
        self.tie_order = np.argsort(-self.prior, kind='stable')
        self.global_mode = self.genres[self.tie_order[0]]
        return self

    def predict(self, users):
        users = pd.Index(users, dtype='string')
        n = self.history.reindex(users, fill_value=0).to_numpy(dtype=float)
        if self.global_only:
            scores = np.broadcast_to(self.prior, (len(users), len(self.genres)))
        else:
            counts = self.counts.reindex(users, fill_value=0).to_numpy(dtype=float)
            denom = n + self.alpha
            scores = np.divide(counts + self.alpha * self.prior, denom[:, None],
                               out=np.broadcast_to(self.prior, counts.shape).copy(),
                               where=denom[:, None] > 0)
        best = self.tie_order[np.argmax(scores[:, self.tie_order], axis=1)]
        return pd.DataFrame({'author_steamid': users,
                             'recommended_genre': np.asarray(self.genres)[best],
                             'history_count': n.astype(int),
                             'score': scores[np.arange(len(users)), best]})

4. Holdout protocol and results

Sort by max(timestamp_created, timestamp_updated) and use global 70/15/15 chronological partitions, keeping timestamp ties together. Last-update time is used because the stored review vote may have changed after creation. This tests later available positive review states, not strictly first-time purchases.

Choose the model using training and validation only; refit its selected configuration on train + validation and evaluate the test period with frozen histories. A warm user has positive history in the fitted partition. Cold users are included rather than silently removed. Training genre metadata is a present-day snapshot, so historical taxonomy changes remain an unresolved limitation.

Primary metric: average the binary genre hit across reviews within each user, then across users. This gives every evaluated user equal weight. Also show review-weighted hits and warm/cold cohorts. This is multi-label Hit@1, not single-label classification accuracy, recall of all interests, or causal evidence that a recommendation improves satisfaction.

5. Findings, limitations and discussion for the meetup

  • Use personal genre mode with global Indie fallback as the current selected model. It is best among the tested configurations; factorization and learned classifiers have not been compared.
  • Discuss whether Indie belongs in the prediction vocabulary and whether to predict a single favorite genre or retain the current multi-label future-review proxy.
  • Cold start is the main coverage limitation. Optional preference onboarding or additional historical user data could help; current lifetime ownership/playtime aggregates cannot safely be treated as past features.
  • Positive-only reviews are an explicit feedback proxy. Missing or negative reviews do not establish dislike of every genre. The sample may be biased by which games and users were collected.
  • Chronological evaluation has no future interactions in fitted profiles, but snapshot genres and unavailable edit histories prevent a fully historical replay.
  • For later experiments, consider historical-text features, recency weights, collaborative filtering, and an Indie-excluded target. Reserve a fresh final holdout before further tuning against these observed test results.
